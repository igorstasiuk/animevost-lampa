# Тестирование плагина

1. `npm run lint && npm test` (нужен интернет; ~1–3 минуты). Итог: `N passed, M failed, js errors: K`.
2. **Падение**: открой сценарий в `test/full.js` по номеру из вывода. Различай: (а) сбой сети/API → повтори; (б) баг плагина → опиши `animevost.js:строка`; (в) устаревшая заглушка → сверь с бандлом (`sh tools/lampa-grep.sh`) и поправь `mk()`.
3. **Новый сценарий**: скопируй соседний блок «N. …» в конец перед итоговой строкой. Хелперы: `mk(apiUrl?)` — новый стенд; `S.key('content'|'animevost_dd', 'up|down|left|right|back')`; `S.$(S.focused).trigger('hover:enter'|'hover:long')`; `S.sel`/`S.modal`/`S.input` — последнее открытое окно/ввод; `until(cond, tries)`; `ok(cond, 'описание')`.
4. **Обязательные негативные случаи**: мёртвый API (`mk('http://127.0.0.1:9/v1')`), `destroy()` во время загрузки, быстрые повторные действия, пустые данные, границы рядов, возврат из окон.
5. **Циклы навигации — только с ограничением итераций** (бесконечный `while` ранее съел всю память).
6. **Чистые функции**: `require('../animevost.js')`, проверка на живых данных API (длинные франшизы, без дат, 200+ серий).
7. **Отчёт — честно о границах**: jsdom не считает раскладку (`offsetTop = 0`), не проверяет реальный фокус на ТВ, внешний Android-плеер, нативный запрос сайта, IndexedDB на устройстве. Локальный HTTP-сервер и `file:` в браузерных инструментах могут быть запрещены — не обходить.
8. Для глубокой проверки можно запустить агентов `plugin-qa` (дописать сценарии) и `tv-nav-reviewer` (ревью фокуса).
